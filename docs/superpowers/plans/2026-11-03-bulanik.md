# bulanik Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `bulanik` v0.1.0. It is a dependency-free Python fuzzy library with:
- fuzzy numbers, aggregation and scales;
- fuzzy sets and inference (Mamdani, Sugeno, Tsukamoto, interval type-2, ANFIS);
- crisp and fuzzy MCDM;
- optional LumiX and sezgi bridges;
- 16 runnable examples.

**Architecture:**
- The core lives under `src/bulanik`. It imports only the standard library, uses floats only (no numpy), and uses frozen dataclasses with validated constructors.
- Every operator family, score, normalisation and defuzzifier is chosen by name. Results report the names that were used.
- `bulanik.lumix` and `bulanik.sezgi` are separate bridge modules. They import their extra at module import time. `bulanik/__init__` never imports them.

**Tech Stack:** Python ≥ 3.10, hatchling, uv, pytest, hypothesis, pytest-cov; extras lumix-opt ≥ 0.3.2 + ortools ≥ 9.8, sezgi ≥ 0.1.6.

**Spec:** `docs/superpowers/specs/2026-11-03-bulanik-design.md`, including amendments f18643c (goal 4b) and 00f3517 (goal 4c). The spec is the binding authority. Where this plan rules on something the spec leaves open, the ruling is marked **Ruling** with its source.

## Review Focus

1. **Zero weights and degenerate inputs in aggregation.**
   - WA/WG with a weight of 0 must ignore that input. This relies on λA with λ=0 being the ⊕ identity, with `0.0**0 == 1`.
   - All-zero weights with `normalize=True` must raise `ValueError`, not divide by zero.
   - Test: Task 4 `test_zero_weight_drops_input` and `test_all_zero_weights_raise`.
2. **Constant criterion columns in crisp MCDM.** A column where every alternative has the same value must not raise `ZeroDivisionError`. That covers TOPSIS norm 0, VIKOR f\* = f⁻, EDAS SP = 0 and entropy uniform. Such a column contributes nothing, and the result is still a valid ranking. Test: Task 11 `test_constant_column_is_neutral`.
3. **Ties in rankings.** Equal scores must rank stably in input order, so runs are reproducible. Test: Task 11 `test_ties_keep_input_order`.
4. **FIS inputs that are missing, extra or outside the universe.** These raise a `ValueError` naming the variable and its universe, never a silent clamp. Test: Task 6 `test_input_errors_are_clear`.
5. **Float noise at the constraint boundary.**
   - `PFN(0.6, 0.8)` has μ²+ν² = 1.0000000000000002 and must be accepted.
   - Results of repeated ops must stay valid.
   - Test: Task 2 `test_boundary_float_noise_accepted` and the hypothesis closure tests.

**Rulings for this task:**
- **Arithmetic:** the standard approximate formulas in their general-sign form (Chen & Hwang 1992 interval-vertex arithmetic).
  - `A+B = (l1+l2, m1+m2, u1+u2)`;
  - `A−B = (l1−u2, m1−m2, u1−l2)`;
  - `A*B = (min P, m1·m2, max P)`, where P = {l1l2, l1u2, u1l2, u1u2};
  - `A/B = A * (1/u2, 1/m2, 1/l2)`, and raises ValueError when `l2 ≤ 0 ≤ u2`;
  - `k*A` swaps ends for k < 0;
  - `A**p = (l^p, m^p, u^p)` for p ≥ 0 and `(u^p, m^p, l^p)` for p < 0. It needs `l ≥ 0` (or `l > 0` when p < 0), and raises ValueError otherwise.
  - TrFN is the same with 4 points.
- **Defuzzification:**
  - `centroid` is the area centroid: TFN `(l+m+u)/3`; TrFN `(d²+c²+cd−a²−b²−ab)/(3(d+c−a−b))`, or `a` when all four are equal.
  - `graded_mean` is Chen & Hsieh's graded mean integration: TFN `(l+4m+u)/6`; TrFN `(a+2b+2c+d)/6`.
  - `mean` is the arithmetic mean of the defining points: TFN `(l+m+u)/3`, the same as centroid; TrFN `(a+b+c+d)/4`.
  - The default is `centroid`.
- **Vertex distance:** Chen 2000, `sqrt(Σ(Δ)²/3)` for TFN and `/4` for TrFN.
- **Mixed types:** TFN ⊕ TrFN returns `NotImplemented`, which surfaces as a TypeError. `ops="einstein"` on a TFN raises ValueError listing `algebraic`.

### Task 2: q-rung orthopair numbers (QROFN, IFN, PFN, FFN)

**Files:** Create `src/bulanik/numbers/orthopair.py` and `tests/test_orthopair.py`. Modify `numbers/__init__.py`, `bulanik/__init__.py` and `tests/strategies.py` (add `qrofns(q)`).

**Interfaces:**
- Consumes: `FuzzyNumber`, `unit`, `choose` and `TOL` from Task 1.
- Produces:
  - `QROFN(mu: float, nu: float, q: int)`: frozen, with `q` an int ≥ 1 and μ^q+ν^q ≤ 1 + TOL. It has `complement()`, `hesitancy -> float` (π = (1−μ^q−ν^q)^(1/q)), `OPS=("algebraic","einstein")`, `SCORES=("difference","normalized")`, `DEFAULT_SCORE="difference"`, `ACCURACIES=("sum",)`, `DISTANCES=("hamming","euclidean")` and `DEFAULT_DISTANCE="hamming"`.
  - `IFN(mu, nu)` (q=1), `PFN(mu, nu)` (q=2) and `FFN(mu, nu)` (q=3) are subclasses with a fixed q. Every op returns the class of `self`. `repr` is `IFN(mu=0.6, nu=0.3)`.
  - Combining different q values or classes raises TypeError via `same_kind`.

**Rulings (formulas):**
- **The transform.** Every q-rung op is the intuitionistic op applied to (a, b) = (μ^q, ν^q), followed by the q-th root of each part. Spec §6 leaves "how the q-rung Einstein operations are expressed" to the builder. This transform reproduces:
  - Liu & Wang 2018 (Int J Intell Syst 33:259–280) for algebraic;
  - Wang & Liu 2011/2012 (Int J Intell Syst 26:1049–1075; IEEE TFS 20:923–938) for Einstein at q=1;
  - Garg 2016 (Int J Intell Syst 31:886–920) for Einstein at q=2.
- **Algebraic (on a, b):**
  - `⊕`: a=a1+a2−a1a2, b=b1b2;
  - `⊗`: a=a1a2, b=b1+b2−b1b2;
  - `λA`: a=1−(1−a)^λ, b=b^λ;
  - `A^λ`: a=a^λ, b=1−(1−b)^λ.
- **Einstein (on a, b):**
  - `⊕`: a=(a1+a2)/(1+a1a2), b=b1b2/(1+(1−b1)(1−b2));
  - `⊗`: a=a1a2/(1+(1−a1)(1−a2)), b=(b1+b2)/(1+b1b2);
  - `λA`: a=((1+a)^λ−(1−a)^λ)/((1+a)^λ+(1−a)^λ), b=2b^λ/((2−b)^λ+b^λ);
  - `A^λ`: a=2a^λ/((2−a)^λ+a^λ), b=((1+b)^λ−(1−b)^λ)/((1+b)^λ+(1−b)^λ).
- **λ:** must be ≥ 0. λ = 0 is allowed, because it makes zero weights work: 0·A = (0,1) and A^0 = (1,0).
- **Scores:**
  - `difference` = μ^q−ν^q, the default (Liu & Wang 2018; Chen & Tan 1994 at q=1);
  - `normalized` = (1+μ^q−ν^q)/2 ∈ [0,1], a linear rescale of the default for methods that need non-negative input;
  - accuracy `sum` = μ^q+ν^q (Hong & Choi 2000 at q=1; Liu & Wang 2018).
- **Distances.** These are Szmidt & Kacprzyk 2000 three-term distances, applied to the q-th powers:
  - `hamming` = (|Δμ^q|+|Δν^q|+|Δπ^q|)/2;
  - `euclidean` = sqrt((Δμ^q²+Δν^q²+Δπ^q²)/2);
  - both lie in [0,1].
- **Complement:** (ν, μ).

### Task 3: Three-part numbers (SphericalFN, PictureFN, NeutrosophicFN)

**Files:** Create `src/bulanik/numbers/threepart.py` and `tests/test_threepart.py`. Modify the exports and `tests/strategies.py` (add `sphericals()`, `pictures()`, `neutrosophics()`).

**Interfaces:**
- Consumes: Task 1 base and helpers.
- Produces:
  - `_ThreePart(FuzzyNumber)`: the shared base. It stores `parts: tuple[float, float, float]`, implements `distance` via a per-class `_simplex_parts()` hook, and has `OPS=("algebraic",)`.
  - `SphericalFN(mu, nu, pi)`: μ²+ν²+π² ≤ 1. `SCORES=("pi_adjusted","normalized")`, default `pi_adjusted`; `ACCURACIES=("sum",)`.
  - `PictureFN(mu, eta, nu)`: μ+η+ν ≤ 1. `SCORES=("difference","normalized")`; `ACCURACIES=("sum",)`.
  - `NeutrosophicFN(t, i, f)`: each part in [0,1]. `SCORES=("average",)`; `ACCURACIES=("difference","certainty")`, default `difference`.
  - All three have `DISTANCES=("hamming","euclidean")`, default `hamming`.

**Rulings:**
- **No Einstein family.** None of the three types offers Einstein in v0.1, so `ops="einstein"` raises ValueError listing `algebraic`. The spec only asks for Einstein "where the literature defines them". The Einstein definitions for these types are scattered and I could not pin a canonical source for them. Adding Einstein later is an additive change.
- **Spherical** (Kutlu Gündoğdu & Kahraman 2019, J Intell Fuzzy Syst 36:337–352):
  - `⊕`: μ=√(μ1²+μ2²−μ1²μ2²), ν=ν1ν2, π=√((1−μ2²)π1²+(1−μ1²)π2²−π1²π2²);
  - `⊗`: μ=μ1μ2, ν=√(ν1²+ν2²−ν1²ν2²), π=√((1−ν2²)π1²+(1−ν1²)π2²−π1²π2²);
  - `λA`: μ=√(1−(1−μ²)^λ), ν=ν^λ, π=√((1−μ²)^λ−(1−μ²−π²)^λ);
  - `A^λ`: μ=μ^λ, ν=√(1−(1−ν²)^λ), π=√((1−ν²)^λ−(1−ν²−π²)^λ);
  - score `pi_adjusted` = (μ−π)²−(ν−π)², accuracy `sum` = μ²+ν²+π²; `normalized` = (1+score)/2;
  - complement = (ν, μ, π).
- **Picture** (Cuong 2014, J Comput Sci Cybern 30:409–420; ops and WA/WG from Wei 2017, J Intell Fuzzy Syst 33:713–724):
  - `⊕`: (1−(1−μ1)(1−μ2), η1η2, ν1ν2);
  - `⊗`: ((μ1+η1)(μ2+η2)−η1η2, η1η2, 1−(1−ν1)(1−ν2));
  - `λA`: (1−(1−μ)^λ, η^λ, ν^λ);
  - `A^λ`: ((μ+η)^λ−η^λ, η^λ, 1−(1−ν)^λ);
  - score `difference` = μ−ν (Wei 2017), `normalized` = (1+μ−ν)/2, accuracy `sum` = μ+η+ν;
  - complement = (ν, η, μ).
- **Neutrosophic, single-valued** (Wang et al. 2010; ops and score from Peng et al. 2016, Int J Syst Sci 47:2342–2358):
  - `⊕`: (t1+t2−t1t2, i1i2, f1f2);
  - `⊗`: (t1t2, i1+i2−i1i2, f1+f2−f1f2);
  - `λA`: (1−(1−t)^λ, i^λ, f^λ);
  - `A^λ`: (t^λ, 1−(1−i)^λ, 1−(1−f)^λ);
  - score `average` = (2+t−i−f)/3, accuracy `difference` = t−f, `certainty` = t;
  - complement = (f, 1−i, t).
- **Distances.** These follow the same simplex rule as Task 2, and each lies in [0,1].
  - Spherical uses the squares (μ², ν², π², r²) with refusal r² = 1−μ²−ν²−π², and divides the L1 sum by 2 (Euclidean: √(Σ/2)).
  - Picture uses (μ, η, ν, ρ) with ρ = 1−μ−η−ν, also divided by 2.
  - Neutrosophic uses (t, i, f) divided by 3 (Euclidean √(Σ/3)), as in Majumdar & Samanta 2014.

**Interfaces:**

### Task 5: Fuzzy sets, linguistic variables, t-norms and linguistic scales; example 02

**Files:** Create `src/bulanik/sets.py`, `src/bulanik/scales.py`, `tests/test_sets.py`, `tests/test_scales.py` and `examples/02_scale_and_experts.py`. Modify `tests/test_examples.py` and the README.

**Interfaces:**
- Consumes: TFN and IFN, plus `aggregate_experts`.
- Produces (`bulanik.sets`):
  - `MembershipFunction`: frozen, with `kind: str` and `params: tuple[float, ...]`. It has `__call__(x: float) -> float`, `is_monotonic: bool` and `inverse(alpha: float) -> float`. `inverse` raises ValueError for non-monotonic kinds and for alpha outside [0,1].
  - Factories:
    - `triangular(a, b, c)`;
    - `trapezoidal(a, b, c, d)`;
    - `gaussian(mean, sigma)` with sigma > 0;
    - `bell(a, b, c)`, the generalized bell `1/(1+|(x−c)/a|^(2b))` with a > 0 and b > 0;
    - `sigmoid(slope, center)`, i.e. `1/(1+exp(−slope(x−center)))`, with slope ≠ 0;
    - `linear_increasing(a, b)`: 0 for x ≤ a, 1 for x ≥ b;
    - `linear_decreasing(a, b)`: 1 for x ≤ a, 0 for x ≥ b. Both linear kinds need a < b.
    - Shoulders are allowed: `triangular(0, 0, 5)` has μ(0) = 1.
  - `is_monotonic` is True only for `linear_increasing`, `linear_decreasing` and `sigmoid`.
  - Inverses:
    - linear_increasing: `a+α(b−a)`;
    - linear_decreasing: `b−α(b−a)`;

- Produces (`bulanik.inference.rules`):
  - `Term(variable: str, term: str, negated: bool = False)`, with `__and__ -> And`, `__or__ -> Or` and `__invert__ -> Term(negated=not negated)`.
  - `And(parts: tuple)` and `Or(parts: tuple)`, each with `&` and `|`.
  - `Rule(antecedent: Term | And | Or, consequents: Mapping[str, str], weight: float = 1.0)`, where weight is in [0,1]. `str(rule)` gives canonical text that `parse_rule` round-trips.
  - `parse_rule(text: str) -> Rule`.
  - `firing_strength(antecedent, degrees: Mapping[str, Mapping[str, float]], and_method: str, or_method: str) -> float`. NOT is 1−μ.
  - `RuleActivation(rule: str, strength: float)`. `strength` is the weight × the antecedent degree; IT2 reuses it with `strength: tuple[float, float]`.
  - `Explanation(degrees: dict[str, dict[str, float]], activations: tuple[RuleActivation, ...], outputs: dict[str, float])`.
  - `NoRuleFiredError(ValueError)`.
- Produces (`bulanik.inference.mamdani`):
  - `MamdaniFIS(inputs: Sequence[LinguisticVariable], outputs: Sequence[LinguisticVariable], rules: Sequence[Rule | str], *, and_method="min", or_method="max", implication="min", aggregation="max", defuzzification="centroid", resolution: int = 1001, default: Mapping[str, float] | None = None)`. It has `evaluate(inputs: Mapping[str, float]) -> dict[str, float]` and `explain(inputs) -> Explanation`, plus the read-only attributes `inputs: tuple[LinguisticVariable, ...]`, `outputs: tuple[LinguisticVariable, ...]` and `rules: tuple[Rule, ...]` (string rules are parsed). Every FIS class in Tasks 7–8 exposes the same three attributes.
  - `defuzzify_samples(xs: Sequence[float], mus: Sequence[float], method: str) -> float`.
  - The method names are:
    - `and_method`: min, prod;
    - `or_method`: max, probor;
    - `implication`: min, prod;
    - `aggregation`: max, sum, probor;
    - `defuzzification`: centroid, bisector, mom, som, lom.
- **Rule grammar.** Keywords are case-insensitive; names are case-sensitive identifiers.

```
rule       := "IF" or_expr "THEN" consequent ("AND" consequent)* ["WITH" number]
or_expr    := and_expr ("OR" and_expr)*          # AND binds tighter than OR
and_expr   := atom ("AND" atom)*
atom       := "(" or_expr ")" | IDENT "IS" ["NOT"] IDENT
consequent := IDENT "IS" IDENT                   # no NOT in consequents
```

  A parse error raises ValueError quoting the offending token and its character offset.
- **Rulings:**
  - The FIS validates every rule at construction. An unknown variable or term raises ValueError listing the valid ones. `default`, when given, must cover every output.
  - `evaluate` needs exactly the input names. A missing or extra key, or a value outside a universe, raises ValueError (Review Focus 4). There is no clamping.
  - **Evaluation:**
    - sample each output universe at `resolution` evenly spaced points, endpoints included (resolution ≥ 2);
    - implied_k(x) = imp(α_k, μ_term(x));
    - aggregate over rules per output (`sum` is not clipped, as in MATLAB's `sum`);
    - defuzzify;
    - if an output's aggregated samples are all 0, either return `default[output]` or raise `NoRuleFiredError` naming the output.
  - **Defuzzification over samples:**
    - centroid = Σxμ/Σμ;
    - bisector = the first sample where the running Σμ ≥ Σμ/2;
    - mom/som/lom = the mean, min or max of the samples with μ ≥ max μ − 1e-12.

### Task 8: Interval type-2 FIS (`bulanik.type2`); example 14

**Files:** Create `src/bulanik/type2.py`, `tests/test_type2.py` and `examples/14_it2_vs_t1_noise.py`. Modify `tests/test_examples.py` and the README.

**Interfaces:**
- Consumes: `MembershipFunction` and its factories, `LinguisticVariable`, `rules.py` (the parser, `Term`, `And`, `Or`, `NoRuleFiredError`, `RuleActivation`, `Explanation`), `SugenoOutput` and `Linear`.
- Produces:
  - `IT2MF(upper: MembershipFunction, lower: MembershipFunction)`. `__call__(x) -> tuple[float, float]` returns (lower, upper) and raises ValueError when lower > upper + TOL at x.
  - Factories:
    - `gaussian_uncertain_mean(mean_low, mean_high, sigma)`: the upper is 1 on [m1,m2] and otherwise the gaussian of the nearer mean; the lower is min(g_m1, g_m2) (Mendel 2001, Uncertain Rule-Based Fuzzy Logic Systems).
    - `gaussian_uncertain_sigma(mean, sigma_low, sigma_high)`: the upper uses sigma_high and the lower uses sigma_low.
    - `scaled_triangle(a, b, c, height)`: the upper is tri(a,b,c) and the lower is height·tri(a,b,c), with 0 < height ≤ 1.
    - The upper and lower of uncertain-mean and scaled-triangle are new `MembershipFunction` kinds (`gaussian_flat_top`, `gaussian_min_pair`, `scaled_triangular`), all non-monotonic.
  - `IT2LinguisticVariable(name, universe, terms: Mapping[str, IT2MF])`, with `fuzzify(x) -> dict[str, tuple[float, float]]` and the classmethod `from_type1(lv: LinguisticVariable)`, which sets lower = upper.
  - `TypeReduced(left: float, right: float, output: float, left_switch: int | None, right_switch: int | None)`, frozen.
  - `type_reduce(ys: Sequence[float], lower: Sequence[float], upper: Sequence[float], method: str = "km", *, bmm_m: float = 0.5, bmm_n: float = 0.5) -> TypeReduced`. The methods are `km`, `ekm`, `nie_tan` and `bmm`.
  - `IT2MamdaniFIS(inputs: Sequence[IT2LinguisticVariable], outputs: Sequence[IT2LinguisticVariable], rules, *, and_method="min", or_method="max", implication="min", aggregation="max", type_reduction="km", resolution=1001, default=None)`.
  - `IT2SugenoFIS(inputs: Sequence[IT2LinguisticVariable], outputs: Sequence[SugenoOutput], rules, *, and_method="min", or_method="max", type_reduction="km", default=None)`.
  - Both have `evaluate(inputs) -> dict[str, float]` (the midpoint output), `evaluate_interval(inputs) -> dict[str, TypeReduced]` and `explain(inputs) -> Explanation`, where each `RuleActivation.strength` is `(f_lower, f_upper)`.
- **Rulings (algorithms):**
  - **Firing interval:** f_lower is the antecedent over the lower degrees and f_upper is the antecedent over the upper degrees. NOT maps (lo, hi) to (1−hi, 1−lo). The rule weight multiplies both bounds.
  - **Mamdani:** at each output sample x_i, upper(x_i) = agg_k imp(f̄_k, μ̄_k(x_i)) and lower(x_i) = agg_k imp(f_k, μ_k(x_i)). Then `type_reduce(xs, lower, upper)`. This is the centroid type reducer.
  - **Sugeno:** `type_reduce([z_k], [f_k], [f̄_k])`. This is the centre-of-sets type reducer.
  - **No rule fired:** the policy applies when Σ upper = 0.
  - **KM** (Karnik & Mendel 2001, Inf Sci 132:195–220):
    1. Sort by y, carrying the weights.
    2. For y_l, start from θ = (lo+hi)/2 and c = Σyθ/Σθ.
    3. Find the switch L (1-based) with y_L ≤ c ≤ y_{L+1}.
    4. Use hi weights for k ≤ L and lo weights for k > L, and recompute c.
    5. Stop when L repeats.
    6. y_r is the same with lo for k ≤ R and hi for k > R.
    7. Output = (y_l+y_r)/2.
  - **EKM** (Wu & Mendel 2009, IEEE TFS 17:923–934): the same fixed point. It initialises L = round(N/2.4) and R = round(N/1.7) and updates incrementally. Its results must equal KM's.
  - **Nie–Tan** (Nie & Tan 2008, FUZZ-IEEE): y = Σy(lo+hi)/Σ(lo+hi); left = right = output, and switches are None.
  - **BMM** (Begian, Melek & Mendel 2008, FUZZ-IEEE): y = m·(Σlo·y/Σlo) + n·(Σhi·y/Σhi), with m = n = 0.5 by default. left/right are the two weighted averages, sorted. Σlo = 0 raises ValueError suggesting `km`.
  - **Input validation:** the lengths must match; 0 ≤ lo ≤ hi; Σhi > 0.

**Interfaces:**
- Consumes: `gaussian`, `bell`, `LinguisticVariable`, `SugenoFIS`, `SugenoOutput` and `Linear`.
- Produces:
  - `_linalg.solve_spd(a: list[list[float]], b: list[float]) -> list[float]`. This is a Cholesky solve. It raises ValueError when the matrix is not positive definite.

  - **Structure** (Jang 1993, IEEE SMC 23:665–685): grid partition, rules in `itertools.product` order of MF indices, AND = product, normalised firing w̄, output Σw̄_r(p_r·x + r_r).

    - bell a = that same width, b = 2, c = centre.
    - `ranges=None` takes the min and max of X at the first `fit`. `predict` before `fit` without ranges raises RuntimeError.

  - **Gradient method:** consequents start at 0, and each epoch takes one batch gradient step on all parameters with the same `lr`.
  - The spec's "small pure-Python solver (QR or a regularised normal equation)": the regularised normal equation with Cholesky is chosen.
  - The spec's "fixed seed": the training is deterministic, so the reproducibility is by construction. The ANFIS tests use deterministic grid data.
  - Learning rate: a fixed `lr` (Jang's adaptive step-size heuristic is not in v0.1).

    - `swara(comparative_importance: Sequence[float | FuzzyNumber], criteria: Sequence[str], *, score: str | None = None) -> WeightingResult`;
    - `entropy(matrix: Sequence[Sequence[float]], criteria=None) -> WeightingResult`.
- **Rulings:**
  - **AHP** (Saaty 1980):
    - the matrix must be square, positive and reciprocal (a_ij·a_ji = 1 within 1e-9, diagonal 1);
    - weights are the principal eigenvector by power iteration (tolerance 1e-12, at most 1000 iterations), normalised;
    - λmax = mean_i (Aw)_i/w_i, CI = (λmax−n)/(n−1);
    - CR = CI/RI with RI = {1:0, 2:0, 3:0.58, 4:0.90, 5:1.12, 6:1.24, 7:1.32, 8:1.41, 9:1.45, 10:1.49}, and CR = 0 for n ≤ 2;
    - n > 10 raises ValueError (no RI);
    - `operators={"weights": "eigenvector", "consistency": "saaty_ri"}`.
  - **Fuzzy AHP** (Buckley 1985):
    - the TFN matrix must be reciprocal (a_ji equals a_ij.reciprocal() within 1e-9);
    - r_i = (Π_j a_ij)^(1/n) componentwise;
    - fuzzy w_i = r_i ⊗ (Σr)^−1, where (Σr)^−1 = (1/Σu, 1/Σm, 1/Σl);

    - CR = `ahp` CR of the matrix of defuzzified entries (spec §2.6). The defuzzified matrix is not exactly reciprocal, so the CR uses the eigen computation without the reciprocity check;
    - `operators={"weights": "buckley_geometric_mean", "defuzzification": <name>, "consistency": "saaty_ri"}`.
  - **SWARA** (Keršulienė, Zavadskas & Turskis 2010, J Bus Econ Manag 11:243–258):
    - criteria are given most important first; `comparative_importance` has length n−1 (s_2..s_n), and each s ≥ 0;
    - k_1 = 1, k_j = s_j+1, q_1 = 1, q_j = q_{j−1}/k_j, w = q/Σq;
    - fuzzy entries go through `x.score(score)`, where `score=None` is the type default; a negative score raises ValueError suggesting `score="normalized"`;
    - `operators={"score": <resolved name or "crisp">}`.
  - **Entropy** (Shannon; Hwang & Yoon 1981):
    - p_ij = x_ij/Σ_i x_ij, E_j = −Σp ln p / ln m (with 0 ln 0 = 0), d_j = 1−E_j, w = d/Σd;
    - needs x ≥ 0, column sums > 0 and m ≥ 2;
    - if every d_j = 0, raise ValueError ("no criterion discriminates").

- **Rulings:**
  - **TOPSIS** (Hwang & Yoon 1981):
    - r = x/√Σx² per column, v = w·r;
    - A+ is the max for benefit and the min for cost; A− is the opposite;
    - Euclidean d±, C = d−/(d++d−), ranked descending;
    - a zero-norm column gives r = 0;
    - if d++d− = 0, C = 0.5 (all alternatives identical);
    - extras `d_plus` and `d_minus`;
    - `operators={"normalization": "vector", "distance": "euclidean"}`.
  - **VIKOR** (Opricovic & Tzeng 2004, EJOR 156:445–455):
    - f* is best, f− is worst;
    - S_i = Σw_j(f*_j−f_ij)/(f*_j−f−_j), R_i = max_j of the same;
    - Q = v(S−S*)/(S−−S*) + (1−v)(R−R*)/(R−−R*), with v = 0.5 by default ("voting by majority", Opricovic & Tzeng 2004);
    - a criterion with f* = f− contributes 0;
    - a zero denominator in Q makes that term 0;
    - ranked ascending by Q; extras `S` and `R`;
    - `operators={"normalization": "linear_range", "v": "0.5"}`, with the actual value as a string;
    - the compromise-acceptability conditions C1/C2 are not in v0.1.
  - **WASPAS** (Zavadskas et al. 2012, Elektronika ir Elektrotechnika 122:3–6):
    - linear max normalisation: benefit x/max_i x, cost min_i x/x;
    - Q = λΣw·x̄ + (1−λ)Πx̄^w, with λ = 0.5;
    - all entries must be > 0 (ValueError otherwise, suggesting `score="normalized"`);
    - extras `wsm` and `wpm`; `operators={"normalization": "linear_max", "lambda": "0.5"}`.
  - **EDAS** (Keshavarz Ghorabaee et al. 2015, Informatica 26:435–451):
    - AV_j = column mean;
    - PDA/NDA are the positive and negative distances from AV divided by AV, with direction by type;
    - SP and SN are weighted sums, NSP = SP/max SP, NSN = 1−SN/max SN, AS = (NSP+NSN)/2;
    - AV ≤ 0 raises ValueError;
    - max SP = 0 makes NSP = 0, and max SN = 0 makes NSN = 1;
    - extras `SP`, `SN`, `NSP` and `NSN`; `operators={"normalization": "average_distance"}`.
  - **rank_fuzzy:**
    1. `aggregate_experts(matrix.experts, matrix.expert_weights, method=aggregation, ops=ops)` (a single expert passes through);
    2. `x.score(score)`;
    3. the crisp method.
    - The reported `operators` are the method's own plus `aggregation`, `ops` and `score` (the resolved default name).
  - **fuzzy_topsis** (Chen 2000, FSS 114:1–9):
    - benefit r = (a/c*, b/c*, c/c*) with c* = max_i c_ij; cost r = (a⁻/c, a⁻/b, a⁻/a) with a⁻ = min_i a_ij;
    - ṽ = r ⊗ w̃, componentwise (a crisp w is treated as (w,w,w));
    - FPIS = (1,1,1), FNIS = (0,0,0);
    - d is the sum of vertex distances, CC = d−/(d*+d−), ranked descending;
    - extras `d_star` and `d_minus`; `operators={"normalization": "linear_scale_chen2000", "distance": "vertex"}`.

**Interfaces:**
- Consumes: `BWMResult`, `resolve_best_worst`, `bwm_consistency_index` (Task 12), `ANFIS.get_params/set_params/param_layout/rmse` (Task 9), `SugenoFIS` (Task 7) and TFN.
- The sezgi calls used were verified in `sezgi/py-sezgi/python/sezgi` (0.1.6):
  - subclass `sezgi.Problem` and implement `space()`, which returns `sezgi.Float(lo, hi, n)`, and `evaluate(x: list[float]) -> float` (minimised);
  - `sezgi.DifferentialEvolution(pop_size=40, variant="jde").run(problem, budget=..., seed=...)` returns a `SolveResult` with `best_x`, `best_f` and `evals_used`;
  - there is no native single-objective constraint API, so constraints are penalties in `evaluate`.
- Produces:
  - `scales.FUZZY_BWM_TFN` (Guo & Zhao 2017): `EI` (1,1,1), `WI` (2/3,1,3/2), `FI` (3/2,2,5/2), `VI` (5/2,3,7/2), `AI` (7/2,4,9/2).
  - `mcdm.bwm.fuzzy_bwm_consistency_index(a_bw: TFN) -> float`: the larger root of ξ² − (1+2u)ξ + (u²−u) = 0, with u = a_bw.u. This reproduces Guo & Zhao 2017's CI table (3.00, 3.80, 5.29, 6.69, 8.04) for the five terms.
  - `BWMProblem(best_to_others: Mapping[str, float], others_to_worst: Mapping[str, float], criteria=None, *, best=None, worst=None, penalty: float = 10.0)`:
    - `space()` is `Float(1e-6, 1.0, n)`;
    - `evaluate(x)` = max(|x_B/x_j − a_Bj| for j ≠ B, |x_j/x_W − a_jW| for j ≠ W) + penalty·|Σx − 1|;
    - `solve(algorithm=None, *, budget: int = 20000, seed: int = 0) -> BWMResult`.
  - `FuzzyBWMProblem(best_to_others: Mapping[str, TFN], others_to_worst: Mapping[str, TFN], criteria=None, *, best=None, worst=None, penalty: float = 10.0)`:
    - `space()` is `Float(1e-6, 1.0, 3n)`, laid out as (l, m, u) per criterion;
    - `solve(algorithm=None, *, budget: int = 100000, seed: int = 0) -> BWMResult`;
    - `fuzzy_weights` is filled; `one=TFN(1,1,1)` is used for inference.
  - `ANFISProblem(anfis: ANFIS, X, y, *, coef_bound: float = 10.0)`: `space()` is `Float(0.0, 1.0, D)`, and `evaluate(z)` decodes z affinely to each parameter's bounds, calls `set_params` and returns the RMSE.
  - `train_anfis(anfis: ANFIS, X, y, *, algorithm=None, budget: int = 20000, seed: int = 0, coef_bound: float = 10.0) -> ANFISTrainResult`. It trains a copy and leaves the input untouched.
  - `ANFISTrainResult(anfis: ANFIS, rmse: float, evals_used: int)`, frozen.
  - The default algorithm everywhere is `sezgi.DifferentialEvolution(pop_size=40, variant="jde")`.
  - Missing sezgi gives `ImportError` matching `bulanik[sezgi]`.
- **Rulings:**
  - **Crisp nonlinear BWM** (Rezaei 2015): min ξ subject to |w_B/w_j − a_Bj| ≤ ξ and |w_j/w_W − a_jW| ≤ ξ, Σw = 1. ξ is eliminated as the max of the absolute values.
    - The ratios are scale-invariant, so the weight-sum penalty only fixes the scale. `solve` returns w = x/Σx, which sums to 1 exactly and has the same ξ.
    - The spec's "ordering constraints" have no counterpart in Rezaei's crisp model, so the crisp problem has only the sum penalty.
    - CR = ξ/`bwm_consistency_index(a_BW)`, and 0 when the index is 0.
    - `operators={"model": "nonlinear", "consistency": "rezaei2015_ci", "algorithm": <class name>}`.
  - **Fuzzy BWM** (Guo & Zhao 2017, Knowledge-Based Systems 121:23–31): min k* subject to, for j ≠ B,
    - |l_B − l_Bj·u_j| ≤ k·u_j;
    - |m_B − m_Bj·m_j| ≤ k·m_j;
    - |u_B − u_Bj·l_j| ≤ k·l_j;

    and the same three rows for (j, W) with a_jW, for j ≠ W. That is the TFN division w̃_B/w̃_j = (l_B/u_j, m_B/m_j, u_B/l_j). The model also has Σ R(w̃_j) = 1 with graded mean R = (l+4m+u)/6, and l ≤ m ≤ u.
    - `evaluate` = max over the rows of |·|/denominator + penalty·(|ΣR − 1| + Σ max(0, l−m) + max(0, m−u)). These are the weight-sum and ordering penalties of spec §2.8.
    - **Ruling:** the j = B row of the BO vector and the j = W row of the OW vector are skipped. They are identities in the crisp model, and in the fuzzy one they would force w̃_B to be crisp.
    - `solve` rescales every triple by 1/ΣR, which leaves k unchanged. The crisp weights are R(w̃_j), the fuzzy weights are the TFNs, and CR = k*/`fuzzy_bwm_consistency_index(a_BW)`.
  - **Penalty and budget defaults:** `penalty=10.0`, jDE with pop 40, and budgets of 20000 (crisp) and 100000 (fuzzy). These come from prototype runs. With a penalty of 1e3, rand1 at 60k evaluations stalled at k = 0.74 to 1.44. With penalty 10 and jDE at 100k, seeds 1, 2 and 3 all reached k* = 0.208712.
  - **ANFIS decode bounds,** where span = hi−lo per input:
    - gaussian c ∈ [lo, hi], σ ∈ [span/100, span];
    - bell a ∈ [span/100, span], b ∈ [0.5, 5], c ∈ [lo, hi];
    - consequents ∈ [−coef_bound, coef_bound].
    - A single [0,1] block with an affine decode avoids multi-block space semantics.
  - **Example 12** writes its own `sezgi.Problem` subclass around a `SugenoFIS`. That is the spec's "a FIS can be the evaluated function inside a sezgi.Problem", and no extra bridge class is needed.
