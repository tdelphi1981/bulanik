# bulanik v0.2 — design

Date: 2026-11-04. Request (user): "Tamam v0.2'ye başlayalım." — start v0.2, widening the fuzzy MCDM
coverage of bulanik. The user asked not to be questioned; every decision below is my call.

## Intent
v0.1 covers fuzzy AHP/SWARA/BWM/entropy + TOPSIS/VIKOR/WASPAS/EDAS on TFN, q-rung orthopair,
spherical, picture and neutrosophic numbers. A keyword scan of the publication list (titles +
117 abstracts; counts approximate, overlapping) shows what still blocks reproduction:

| Gap | Papers (approx.) |
|---|---|
| Interval-valued orthopair / neutrosophic numbers (IVIFN, IVPFN, IVFFN, IVNN), mostly with AHP | 24 |
| CODAS ranking | 14 |
| Interval type-2 trapezoidal fuzzy numbers in MCDM | 8 |
| DEMATEL (crisp, fuzzy, interval-valued) | 6 |
| CRITIC weighting | 5 |
| MARCOS, PIPRECIA, CoCoSo, WISP | 3 each |
| COPRAS, ELECTRE | 1 each |

v0.2 adds these, in bulanik's existing style, so a full pipeline can be written in a few lines.

## Goals
1. **New number types** (frozen validated dataclasses, the full `FuzzyNumber` interface: `add`,
   `mul`, `scale`, `power`, `score`, `accuracy`, `distance`, operator families by name, boundary
   projection like v0.1, `aggregate.wa`/`wg` and `aggregate_experts` support):
   - `IVQROFN(mu_l, mu_u, nu_l, nu_u, q)` with aliases `IVIFN` (q=1), `IVPFN` (q=2), `IVFFN` (q=3):
     intervals $[\mu^L,\mu^U]$, $[\nu^L,\nu^U]$ with $(\mu^U)^q + (\nu^U)^q \le 1$. Algebraic and
     Einstein operator families (interval-wise extension of the v0.1 orthopair laws). Scores: the
     standard interval score and accuracy functions from the literature (verify sources; e.g.
     Xu 2007 for IVIFN; Peng & Yang 2016 / Garg 2016 for IVPFN; the Fermatean IV literature).
   - `IVNeutrosophicFN(t_l, t_u, i_l, i_u, f_l, f_u)` (interval neutrosophic, Wang et al. 2005),
     with its standard ops and score/accuracy.
   - `IT2TrFN` — interval type-2 trapezoidal fuzzy number (Chen & Lee 2010): upper and lower
     trapezoids with heights, `upper=(a1,a2,a3,a4,h1,h2)`, `lower=(...)`, lower inside upper.
     Arithmetic of Chen & Lee 2010 (add, sub, mul for non-negative, scalar), named
     defuzzifications/scores including `"dtrat"` (Kahraman et al. 2014) and a centroid-based one,
     and Chen & Lee's ranking value if it can be verified.
   Interval-valued spherical (1 paper) is deferred.
2. **New MCDM methods**, crisp core + `rank_fuzzy` integration (fuzzy ratings → aggregate →
   score → crisp method), each returning the existing result types:
   - Ranking: `codas` (Keshavarz Ghorabaee et al. 2016; Euclidean + taxicab with threshold τ),
     `marcos` (Stević et al. 2020), `cocoso` (Yazdani et al. 2019; λ), `wisp` (Stanujkić et al.
     2021), `copras` (Zavadskas & Kaklauskas 1996), `electre` (ELECTRE I concordance/discordance
     with net concordance/discordance indices for a complete ranking; outranking matrix in extras).
     All registered in `rank_fuzzy(method=...)`.
   - Weighting: `critic` (Diakoulaki et al. 1995), `piprecia` (Stanujkić et al. 2017; crisp and
     TFN relative-importance inputs, like `swara`).
   - Generic fuzzy AHP over any number kind: `fuzzy_ahp` keeps Buckley for TFN; a new
     `ahp_fuzzy_numbers(matrix, criteria, *, aggregation="wg", score=None)` (name to be finalised in
     the plan) aggregates each row with the kind's geometric operator, scores and normalises — the
     common skeleton of the IV/IT2/orthopair AHP papers — with the consistency of the scored
     (crisp) matrix reported. Paper-specific AHP variants are out of scope.
   - **DEMATEL** (`dematel`, Gabus & Fontela 1972): direct-relation matrix (crisp, or TFN/IV
     numbers defuzzified first via a named method, incl. CFCS of Opricovic & Tzeng 2003 for TFN),
     normalisation, total-relation $T = N(I-N)^{-1}$, prominence $D+R$, relation $D-R$,
     cause/effect groups, threshold (mean of T by default), and weights from prominence/relation.
     New result type `DEMATELResult`.
3. **Plotting:** `bulanik.plot` gains `dematel(result)` (cause–effect diagram: prominence on x,
   relation on y, causes above zero, arrows for relations above the threshold — collision-aware
   labels), `iv_orthopair(numbers)` (interval rectangles in the μ–ν plane over the feasible
   region) and `it2_number(number)` (upper/lower trapezoids, shaded FOU). Same house style, light/
   dark, tests, render-and-look.
4. **Docs:** guide pages (interval-valued numbers, IT2 numbers, new ranking methods, new weighting
   methods incl. DEMATEL), gallery figures for the new number types and DEMATEL, API pages,
   examples 18+ (one per family), CHANGELOG 0.2.0, references verified (DOI checked, retractions
   noted), version bump to 0.2.0.

## Constraints (unchanged from v0.1)
- Core stays stdlib-only; Python ≥3.10; public v0.1 API unchanged (additions only).
- Frozen validated dataclasses; named operators/scores with "unknown name lists valid ones" errors;
  bool/str rejected; boundary projection rules as in v0.1.
- Google-style docstrings with doctests; executed docs snippets; strict MkDocs build; coverage gate
  95% enforced; all examples run in tests.
- Formulas must come from the cited source; every source verified (DOI) by the implementing task;
  where literature variants differ, implement the cited one and document it.
- Commits as Tolga Berber, no Claude attribution; no push/tag/publish without the user.

## Non-goals
Bayesian BWM; SPAR-H/FMEA frameworks; forecasting, clustering,
simulation; interval-valued spherical/picture numbers; general type-2 sets; PyPI release.
